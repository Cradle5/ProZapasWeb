# Прозапас — система складского учёта

Одностраничное веб-приложение складского учёта с ролевой моделью доступа,
аутентификацией, защищённым каналом и защищённым локальным хранилищем.
Выполнено в рамках цикла лабораторных работ (лабы 1–17) в веб-реализации.

## Запуск

Приложение — один файл `index.html` без сборки и зависимостей:

- открыть файл в браузере напрямую, **или**
- GitHub Pages: Settings → Pages → Deploy from branch → `main` → ссылка вида
  `https://<логин>.github.io/<репо>/`.

## Роли

| Роль | Возможности |
|------|-------------|
| Руководитель (admin) | всё: цены, закупки, удаление, управление пользователями |
| Бухгалтер (buh) | цены, закупки |
| Товаровед (tovar) | остатки, приход/списание, добавление товаров |

Первый зарегистрированный пользователь автоматически становится руководителем.
Дальнейшие учётные записи создаются руководителем во вкладке «Пользователи».

## Модули по лабораторным работам

- **Лабы 1–5.** Декларативный UI, компоновка, состояние, список товаров с
  пагинацией по 20 («Загрузить ещё»), поиск с debounce 300 мс.
- **Лаба 6.** Навигация и детальный экран: карточка товара по ID из списка или
  по ссылке `?product=ID`; состояние «не найдено» обработано.
- **Лаба 7.** Состояния UI «загрузка / успех / ошибка», кнопка «Повторить»
  заблокирована на 5 секунд (backoff).
- **Лаба 8.** Светлая/тёмная тема с сохранением выбора, aria-label у иконок.
- **Лаба 9.** Анимации интерфейса, уважение `prefers-reduced-motion`.
- **Лаба 10.** Типизированные ошибки канала: HTTP 5xx, ошибка разбора JSON.
- **Лаба 11.** Заметки: файловое хранилище, атомарная запись (tmp → проверка →
  rename), контрольная сумма SHA-256, самовосстановление из резервной копии,
  корзина с авточисткой 30 дней, экспорт/импорт с миграцией формата v0/v1→v2,
  кнопка «Тесты хранилища» — 4 автотеста репозитория.
- **Лаба 12.** Модель угроз STRIDE × DREAD (`threat_model.md`).
- **Лаба 13.** Аутентификация: мок-сервер с JWT (HMAC-SHA256), блокировка после
  4 неудачных попыток, PIN с хешированием, step-up на защищённых разделах,
  одноразовый recovery-код, аудит входов. Access-токен живёт только в памяти.
- **Лаба 14.** Контроль доступа: scope из токена, проверка на трёх уровнях
  (интерфейс → действие → сервер), журнал решений доступа.
- **Лаба 15.** Защищённый канал: подпись HMAC(method+path+body+timestamp+nonce),
  окно ±30 секунд, защита от replay, сценарии атак (replay, подмена, сдвиг
  часов, cleartext, неверный ключ).
- **Лаба 16.** Аудит безопасности: 8 находок, триаж P0/P1/P2 (`audit_report.md`).
- **Лаба 17.** Анализ конкурентов и руководство пользователя (вкладка «Настройки»).

## Данные

Данные хранятся локально в браузере (localStorage) и никуда не отправляются.
Перенос между устройствами — экспорт/импорт JSON. В git попадает только код.

## Структура репозитория

- `index.html` — приложение (весь код в одном файле)
- `demo_data.json` — демо-данные (пароли хранятся только в виде хешей)
- `threat_model.md` — модель угроз (лаба 12)
- `audit_report.md` — отчёт аудита безопасности (лаба 16)
