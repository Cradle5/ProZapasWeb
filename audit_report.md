# Аудит и hardening веб-версии «Прозапас»

**Область:** `stock_control_system.html` v2.0 (vulnerable) → v3.0 (hardened)
**Методика:** OWASP MASVS v2 (адаптация к веб-контексту) + OWASP Top-10; ручной статический анализ кода, анализ хранилища, динамические проверки в DevTools (Console, Network, Application → Local Storage)
**Инструменты:** Chrome DevTools (Console/Network/Application), ручной SAST (просмотр кода на паттерны `innerHTML`, `localStorage.setItem`, `console.log`, отсутствие CSP), gitleaks-аналог (поиск секретов в тексте файла), проверка clipboard

**Итог:** 3 critical, 3 high, 2 medium. Все критические закрыты в hardened-версии v3.0; одна находка закрыта как «риск принят» с обоснованием (FIND-005).

---

## 1. Резюме

Проведён учебный аудит одностраничного веб-приложения складского учёта. В базовой версии (vulnerable) найдено 8 уязвимостей: инъекции через пользовательский ввод, хранение сессии открытым текстом, отсутствие ограничений на перебор пароля, отсутствие CSP, обходимый клиентский RBAC, неограниченный импорт, неочищаемый буфер обмена и журналирование без маскировки. В hardened-версии каждая находка закрыта конкретным механизмом с повторной проверкой.

| Инструмент | Что искал | Как запустить (одной строкой) |

## 3. Находки

### FIND-001 · XSS через пользовательские поля — **Critical 7.4**
- **MASVS/OWASP:** PLATFORM-3 / A03:2021 Injection
- **CVSS:** `AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:L/A:N`
- **Шаги:** создать товар с названием `<img src=x onerror=alert(document.cookie)>` → открыть таблицу склада.
- **Доказательство (vulnerable):** скрипт исполняется, `alert` срабатывает — имя товара вставлялось в `innerHTML` без экранирования.
- **Рекомендация:** экранировать все пользовательские поля (`esc()`), добавить CSP.

### FIND-002 · Сессия и учётные данные в localStorage открытым текстом — **Critical 7.1**
- **MASVS:** STORAGE-1
- **CVSS:** `AV:L/AC:L/PR:L/UI:N/S:C/C:H/I:N/A:N`
- **Шаги:** DevTools → Application → Local Storage → `skotz_v1` → поле `session` содержит идентификатор действующей сессии.
- **Доказательство:** после перезагрузки страницы сессия восстанавливается из хранилища без аутентификации.
- **Рекомендация:** access-токен — только в памяти; refresh — зашифрованный ключом, выведенным из PIN (PBKDF2 + AES-GCM); сессию не сериализовать на диск.

### FIND-003 · Перебор пароля без ограничений — **Critical 8.2**
- **MASVS:** AUTH-2
- **CVSS:** `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N`
- **Шаги:** ввести неверный пароль 20 раз подряд — каждый раз форма принимает попытку без задержек и блокировок.
- **Доказательство:** отсутствуют счётчик попыток и блокировка; логин подбирается автоматическим скриптом.
- **Рекомендация:** 4 неверные попытки → блокировка на 5 минут с таймером; для PIN — лимит 3 попыток со сбросом защищённого хранилища.

### FIND-004 · Отсутствие Content-Security-Policy — **High 6.3**
- **MASVS:** PLATFORM-1
- **CVSS:** `AV:N/AC:L/PR:N/UI:R/S:U/C:L/I:L/A:N`
- **Шаги:** открыть документ в DevTools → нет CSP-заголовка/меты; любой инлайн-скрипт из FIND-001 исполняется свободно.
- **Доказательство:** FIND-001 воспроизводится без препятствий.
- **Рекомендация:** `<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'">` (учебный прототип сохраняет inline-обработчики; целевое состояние — вынос в модуль и отказ от `'unsafe-inline'`).

### FIND-005 · Клиентский RBAC обходится из консоли — **Medium 5.6 (риск принят)**
- **MASVS:** AUTH-1
- **CVSS:** `AV:L/AC:H/PR:L/UI:N/S:U/C:H/I:H/A:L`
- **Шаги:** консоль: `state.users.find(u=>u.role!=='admin').role='admin'; save()` — товаровед получает права руководителя.
- **Доказательство:** вкладка «Пользователи» и отчёты становятся доступны.
- **Рекомендация:** трёхуровневая проверка (UI прячет кнопки → контроллер проверяет scope → «сервер» отклоняет без scope в подписанном токене). **Риск принят:** в учебном прототипе «сервер» эмулируется в той же вкладке; полнота защиты достигается при реальном сервере. Закрытие UI-слоем и серверной проверкой scope.

### FIND-006 · Неограниченный импорт файлов (DoS вкладки) — **Medium 5.3**
- **MASVS:** INPUT-3
- **CVSS:** `AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:L`
- **Шаги:** импортировать файл 200 МБ с миллионами записей — вкладка зависает на сериализации.
- **Доказательство:** замер памяти до/после — рост на сотни МБ.
- **Рекомендация:** лимиты импорта: размер ≤5 МБ, количество ≤10 000; битый JSON отклонять целиком, не частично.

### FIND-007 · Буфер обмена без очистки — **Low 4.2**
- **MASVS:** STORAGE-2
- **CVSS:** `AV:L/AC:L/PR:L/UI:R/S:U/C:L/I:N/A:N`
- **Шаги:** скопировать заявку на закупку → подождать 5 минут → прочитать буфер другим приложением — заявка с суммами всё ещё там.
- **Доказательство:** `navigator.clipboard.readText()` возвращает данные.
- **Рекомендация:** автоочистка буфера через 30 секунд после копирования.

### FIND-008 · Журналирование без маскировки — **High 6.0**
- **MASVS:** RESILIENCE-1
- **CVSS:** `AV:L/AC:L/PR:L/UI:N/S:C/C:H/I:N/A:N`
- **Шаги:** в vulnerable-версии токен сессии мог попасть в `console.log`/историю; проверить: `console.log` c токеном.
- **Доказательство:** поиск по коду показывает вызовы логирования без маскировки.
- **Рекомендация:** не логировать токены нигде; аудит хранит только тип события и причину.

## 5. План hardening (diff vulnerable → hardened)

```
FIND-001: + function esc(s){return String(s||'').replace(/[&<>"']/g,c=>({...}[c]));}
          ~ все вставки пользовательских данных в innerHTML — только через esc()
FIND-002: - save(): JSON.stringify(state)                      # сессия попадала на диск
          + save(): JSON.stringify({...state, session:null})   # access-токен только в памяти
          + encryptRefresh(): PBKDF2(PIN, 150k) → AES-GCM → {salt, iv, ct, exp}
FIND-003: + state.failed счётчик: 4 попытки → state.lockedUntil = now + 5*60*1000
          + PIN: 3 попытки → delete u.refreshEnc (защищённое хранилище сброшено)
FIND-004: + <meta http-equiv="Content-Security-Policy" content="default-src 'self'; ...">
FIND-008: - любые console.log со значениями токенов
          + аудит: только типы событий (LOGIN_OK/LOGIN_FAIL/LOCK/STEP_UP/RECOVERY) и причины
FIND-005: + SCOPE_TABLE + authorize() на контроллере + serverCheck() на «сервере»
FIND-006: + if (f.size > 5MB) reject; if (list.length > 10000) reject
FIND-007: + setTimeout(() => navigator.clipboard.writeText('буфер очищен'), 30000)
```

## 7. RASP-минимум (веб-адаптация)

- Целостность клиентских данных: checksum каждой заметки (SHA-256) с самовосстановлением из резервной копии (л.11).
- Подпись всех мок-запросов HMAC-SHA256; повтор nonce и подмена тела отклоняются сервером (л.15).
- Отказ в праве фиксируется в append-only журнале — попытка без права сама по себе сигнал (л.14).

## 8. Что осталось незакрытым и почему

- **Реальный сервер.** Клиентский RBAC и мок-секрет — осознанные допущения прототипа; перенос на сервер (проверка scope, настоящие JWT с Argon2id) устраняет FIND-005 полностью.
- **2FA/капча** против медленного перебора — следующий шаг после блокировки попыток.
- **Отказ от inline-скриптов** для ужесточения CSP — рефакторинг учебного прототипа.
